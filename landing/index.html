The address bar

Know exactly what you're pointed at.

Before you press Enter, look up. The address bar follows the focused shell and shows the folder, what's running, how the last command went, and the context it's about to touch.

  • Kubernetes, AWS, gcloud, Terraform. The cluster, account, project and workspace the shell uses, as badges.
  • A clock before credentials expire. Don't find out halfway through a deploy.
  • Git branch and who you commit as. Handy with more than one GitHub user.

How wtf treats your setup

Nothing happens behind your back.

A terminal that reaches into your servers, clusters and credentials has to be boringly honest about it.

Real commands

Actions that touch a server, a cluster or AWS run as real commands in a terminal tab: kubectl logs, scp. You see them, they land in your history, and you can run them again yourself.

Shown, then confirmed

Anything that changes a file you own or something in the cloud shows exactly what will change and waits for you. The file is backed up first.

Only when you look

Side-pane tabs load things only while you're looking at them, and stop when you aren't.

Keyboard first

Every command is in one box.

The command palette lists every command with its shortcut. If you learn one shortcut, make it this one. Right-click works nearly everywhere, too: on tabs, hosts, pods, processes, and on the IPs, timestamps and JWTs in your output.

Get wtf

Two platforms. One app.

A native app on each: AppKit and SwiftTerm on macOS, GTK 4 with libadwaita and VTE on Linux, sharing one Go backend.

macOS

Universal: Apple silicon and Intel
wtf-@VERSION@.dmg Disk image wtf-@VERSION@.app.zip App bundle

Open the disk image and drag wtf to Applications.

Linux

Ubuntu 24.04+ · Debian 13+ · Fedora 40+
.deb amd64 .deb arm64 .rpm x86_64 .rpm aarch64

Then sudo apt install ./wtf_*.deb or sudo dnf install ./wtf-*.rpm.

Checksums are in SHA256SUMS on the release page. Prefer to build it yourself? See Install.
